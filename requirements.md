
# Требования к выбору темы проекта
- Наличие бизнес-логики – проект должен включать в себя не просто CRUD-операции, а реализовывать осмысленные вычисления, агрегирование данных, валидации или сложные сценарии обработки запросов.

- Практическая ценность – тема должна решать реальную проблему или автоматизировать какой-то процесс.

- Использование внешних сервисов – приветствуется интеграция с API, базами данных или сторонними источниками данных.

- Не слишком сложная реализация – тема должна быть выполнима за время, отведенное на проект.

# Требования к реализации проекта

## Архитектура:

- Разделение на слои по чистой архитектуре.

- Использование context.Context для управления запросами.

- Конфигурирование через env-переменные или config-файл.

## Работа с данными:

- Использование PostgreSQL/MySQL.

- Использование sqlx, squirrel или аналогичных инструментов для работы с SQL. Не использовать GORM.

- Поддержка миграций (например, migrate) по желанию.

## Эндпоинты:

- Должен быть хотя бы один эндпоинт с бизнес-логикой.

- Обработчики ошибок должны возвращать понятные HTTP-коды и сообщения.

## Безопасность:

- Валидация входных данных.

- Логирование запросов и ошибок.

## Тестирование:

- Unit-тесты для бизнес-логики (на наши юзкейсы).

##  Документация:

- README с описанием проекта и инструкцией по запуску.
